## 0. TL;DR

We are **redesigning the r-science workflow** — turning the old linear
whiteboard→plan→implement pipeline into a **scheduler that walks a tree of hypotheses**,
where **design → plan → (construct) → validate are *moves* on a node**, not global phases.
We are specifying those four moves one at a time by co-writing a spec doc through the
**docloop** human↔LLM review loop. **DESIGN and PLAN are done** (`design.md`, `plan.md`);
**CONSTRUCT and VALIDATE are drafted (v0) and in hash-out**. A separate, already-decided **storage
migration** (GitHub-issue nodes → a native git-backed filesystem/markdown-graph store, #60)
is deliberately **deferred until all four move-specs are finished** (§7).

## 1. What this repository is (background)

**Doktoreltern** is a risk-first methodology for solo / small-scale technical projects,
delivered as a **Claude Code marketplace** (`doktoreltern`) of specialist *advisor* plugins.
It currently ships **two plugins**:

- **`r-science`** — the science-centred R-package development **workflow spine** and its
  supporting skills (`conventions`, `whiteboard`, `plan`, `tests`, `implement`, `verify`,
  `benchmark-optimise`, `review`, plus `r-oop`, `r-bayes`). General-purpose R / GitHub /
  publishing skills it builds on are **not** in this repo — they live upstream in the
  [Posit Claude Skills](https://github.com/posit-dev/skills) marketplace and are pulled in
  as plugin **dependencies**.
- **`docloop`** — a small **Vite + Milkdown GUI** (under `docloop/`) for a human↔LLM
  document-review loop, plus a narrow roster of skills invoked live from inside a review
  comment. **This is the tool we are dogfooding** to co-write the workflow redesign, and
  (not by coincidence) it is also the intended HITL surface for the future node store (§7).

Skills are **structured markdown** that teach Claude a workflow — instructions *for Claude*,
not end-user docs. The one part of the repo with runnable, tested code is the Python
**context substrate** under `r-science/context/` (the marker grammar, fold/linter, fetch
adapter, and an MCP server), with its own pytest suite. `docloop/` is a TypeScript/Vite app
with a Vitest suite. See the repo root `CLAUDE.md` for the authoritative structure notes.

**Where the redesign lives (not in the skills yet):** the redesign is still at the *spec*
stage. The broad design SoT is the **GitHub project wiki** (`workflow-redesign.md`); the
per-move specs are being hashed out in `docloop/workspace/*.md`; the running decision trail
is in Claude memory (`workflow-redesign-active.md`, indexed from `MEMORY.md`). None of this
has been folded back into the actual `r-science` skills yet — that happens after the specs
converge.

## 3. The 60-second frame (keystones — do **not** re-derive these)

Hard-won load-bearing decisions a fresh session must take as given (full trail in memory
`workflow-redesign-active.md`):

- **Fork vs cold-spawn economics.** `fork` = warm (inherits full parent context + cache) but
  **same model, always**. `cold spawn` = ~14k-token floor, any model/effort, clean scoped
  room. ⇒ "cheap + scoped + warm" doesn't exist; changing model/effort *always* pays a cold
  start.
- **Intensity ≠ model/effort.** Intensity = deterministic, cache-safe prompt/skill/breadth
  bundle (dial freely). Model/effort = a cold-restart-costing choice. A finished move emits a
  single **qualitative 0–10 difficulty rating** (per-decision hardness, **not** volume); a
  **deterministic lookup table** routes {rating · current warm model/effort · what intensity
  can absorb} to continue-warm vs cold-spawn.
- **Confidence = provenance ("distance from touching reality"), not self-report**, on **two
  orthogonal axes**: *evidence* (asserted < prior-art < spiked < … < user-tested) ⟂
  *commitment* (unsealed → proposed → sealed). Sealing = **authority, not evidence**; the
  danger cell is **sealed-but-only-asserted**.
- **Doktoreltern = an anti-sycophancy machine.** The human is not right by fiat (wrongness is
  the default); the work *becomes* correct together.
- **Floor-first walking skeleton.** The scheduler drives the whole tree to `interface`
  fidelity (every boundary wired, end-to-end runnable but wrong) before deepening, then goes
  best-first via centrality × (1 − confidence).
- **The move split (design vs plan):** **DESIGN is child-free** and divergent (lands a
  direction + boundary-at-interface + confidence + alternatives). **PLAN is convergent and is
  where the tree grows** — it **creates children**, firms the boundary interface → mock, and
  writes the correctness basis. A **stub-only PLAN** runs in the floor pass.
- **The planner/implementer boundary is the *debug-cycle* boundary.** A stub has no debug
  cycle, so PLAN may write stubs (and, at leaves, the tests); anything that *debugs* is
  CONSTRUCT, held to PLAN's pre-committed criteria.

## 5. DESIGN move — LOCKED (`design.md`)

- **Pipeline:** `reconcile → situate (external) → question (internal) → (spike | reasoning
  deep-dive) → summarise`.
- **situate** = external consistency ("is N *needed*?" vs the nearest **trusted** ancestor);
  fail ⇒ **restructure fault** routed to the offending ancestor, then **stop**. **Has a
  ceiling:** at/above the project boundary correctness is externally unjudgeable, so situate
  degrades to a **coherence** check (asserted-at-root is legitimate if brainstormed).
- **question** = internal consistency; diverge = scout → brainstorm → compare vs ancestor +
  project + plugin desiderata; **breadth is qualitative**, never a count.
- **Confidence** = provenance ladder + distance + staleness; two axes; orders *attention*,
  does **not** hard-gate building (licensed "wrong v1").
- **Boundary** declared at **interface fidelity**; DESIGN is **child-free**.
- **Move-outcome (C↔D seam):** `{ confidence; fault ∈ ok | restructure@ancestor |
  whiteboard-suggested | escalate }` + the 0–10 difficulty rating. **Difficulty ≠ volume:**
  big-but-routine = *low* difficulty, its bigness = many children; difficulty → model tier,
  size → decompose/farm-out, never a bigger model for volume.
- **Resourcing = build the seam, defer the policy:** ship the rating + a swappable
  deterministic router + a usage log; leave the routing *thresholds* blank until real data.
- Now also carries (folded this session): **re-entry is a delta not greenfield** (warm when
  refining N's own resolved question, cold when a premise moved); the Design facet is the
  **design layer of one evolving facet**; **project fission** is a user-signed-off restructure
  variant.
- **Round-1 edits (2026-07-09, still converged):** summarise gained a closing **self-check**;
  move-outcome notes the shared-enum mapping (`restructure@ancestor` ≡ `fault(structure@ancestor)`,
  licensed by evidence-locality since situate reads the ancestor chain); the pipeline box notes
  each move rates the work it hands *forward*.

## 6. PLAN move — LOCKED (`plan.md`)

- **What it is:** the **convergent** counterpart to DESIGN — makes a node **buildable**:
  decompose, firm the boundary interface → mock, specify behaviour + correctness basis. **PLAN
  creates children; DESIGN never does.** Forks **warm** from DESIGN by default.
- **Pipeline:** `decompose → firm-boundary → specify-behaviour → consolidate`. **There is no
  reconcile step** — staleness is the *scheduler's* deterministic job (if a premise moved it
  re-runs DESIGN first), so PLAN gets a current design by construction. The only PLAN→DESIGN
  path is `re-diverge` (converging *exposes a flaw* in the direction — discovered, not a
  pre-check).
- **Fission triggers** (spawn a child vs keep an in-node sub-stage): independent validation
  cohesion (cluster criteria by shared oracle/fixture/dataset), aspect (all-or-none of a
  node), load-bearingness, level (no node is part-implementable/part-decomposing), leaf-too-big
  (more than a weak model does in one CONSTRUCT pass).
- **Walking skeleton:** firming a boundary *to mock* **is** writing a runnable stub, and
  **PLAN writes it** — safe because a stub has **no debug cycle**. Needs a cheap, quiet
  `devtools::check`-style green gate (a **needed substrate tool**).
- **Correctness basis is altitude-dependent (`✅ v`):** at a **leaf** PLAN writes the full
  executable `testthat` suite; at an **internal node** it writes **acceptance requirements**
  (judged by VALIDATE, inherited down as each child's contract).
- **Move-outcome:** `{ build-ready | spawned | reconsider-design | re-diverge |
  restructure@ancestor | escalate }` + per-child difficulty rating; PLAN emits readiness, the
  **scheduler** dispatches CONSTRUCT. **Leaning a single shared fault enum** with DESIGN,
  deferred until CONSTRUCT/VALIDATE are visible.
- **Floor pass** = breadth-first *ordering* (the scheduler's choice), not a mode; a floor-pass
  stub-PLAN does just enough for each child's DESIGN, never the design itself.
- **Deferred/open (documented, not blocking):** ancestor-context breadth (leaning **maximal**,
  revisit against a real project); the resourcing thresholds.
- **Round-1 edits (2026-07-09, still converged):** move-outcome rewritten to the **adopted shared
  enum** (`reconsider-design@N` + `re-diverge` merged into `fault(design@N)`); new **glue leaf**
  paragraph after the fission triggers (+ worked example gains `#3.3`); consolidate gained a
  closing **self-check** + the note that `build-ready` passes through the scheduler's
  **plan-audit**; a **held-out test slice** proposal added to specify-behaviour (awaiting rjs).

## 7. The planned storage migration — DECIDED, NOT YET STARTED

**Current model:** nodes are **GitHub issues** (one-issue-per-node — #16 root epic, #32–47).

**Decision (thread t12, recorded on issue #60):** drop GitHub issues as the backing entirely
and move to a **native git-backed graph store** — filesystem / markdown-graph (the tree is
mostly a tree; aspect cross-cuts are the non-tree edges), so **delta = `git diff <ref>`**
falls out for free, it's portable/offline, and branch/merge mirrors the fork-tree. Issues, if
kept, become a generated projection/index, never the SoT. **docloop is already that store's
git-per-turn HITL surface**, so the two converge — build once. Prior art to scout first:
obsidian/wikilink-graph family (foam, dendron, org-roam) and plain-filesystem DAG stores.

**Sequencing (important):** we are going through **all four move-specs first**
(DESIGN ✅, PLAN ✅, CONSTRUCT, VALIDATE) **before** starting this migration. Rationale: nail
the workflow *semantics* — what each move reads/writes, the fault seam, the facet shape —
before re-platforming the storage they sit on. Do **not** begin the store migration until the
four specs are done, unless rjs says otherwise.

## 8. CONSTRUCT + VALIDATE — hash-out round 1 (2026-07-09, `c745b9a`), awaiting rjs

Round 1 processed rjs's 25 threads (t1–t14 construct, t15–t25 validate; his two turns were
stacked — `turn.xml` showed only the second). 21 replies open, 4 resolved (t9/t10/t22/t23).
What landed (all in-doc now, cross-doc consistent):

- **Only leaves build — the glue leaf (t1, conceded + strengthened).** Internal-node
  CONSTRUCT is gone. PLAN's fission creates a **glue leaf** for non-trivial composition
  (sequential-after siblings); N's boundary mock passes down as its starting artefact; the
  **executable subset of N's acceptance requirements becomes its `✅ v`**. Spec in
  `plan.md` → *The glue leaf*; worked examples now use glue leaf `#3.3`.
- **VALIDATE gained lifecycle dispatch points (t15/t21).** Principle: *arms-length
  validation exists exactly where the consumer cannot judge*. Most seams validate by
  consumption; the one judgement-free consumer is leaf CONSTRUCT → the scheduler runs a
  **plan-audit** (VALIDATE's audit stage alone: cold, cheap, biased-to-fault; fidelity /
  decidability / cold-legibility) before dispatching CONSTRUCT. Internal nodes get
  plan-audit early + **fold-time VALIDATE** late (trigger = fold condition; always runs,
  but shrunk — pushed back on rjs's "only after forced redesign"). Every move gained a
  closing **self-check** (rjs's option 2; catches omissions, not delusions).
- **Evidence-locality (t24, conceded + sharpened).** A move only indicts layers its
  evidence reaches: VALIDATE's faults are **locus-N always**; `(structure, ancestor)`
  withdrawn from its vocabulary. Held the line on VALIDATE keeping `(plan,N)`/`(design,N)`:
  CONSTRUCT catches *impossible* criteria (tier-gated), VALIDATE catches *insufficient* /
  hollow ones. **Ladder walked one hop at a time by successive moves** (t16 — rjs's sketch,
  now a rule). **Shared enum: proposed → adopted**; `reconsider-design@N` + `re-diverge`
  **merged** into `fault(design@N)` (t10 approved; `plan.md` outcome rewritten).
- **Twin dispatch (t11, conceded).** No built-green rung: `built` is a report; fidelity
  *and* evidence rungs are written only by VALIDATE at verdict; CONSTRUCT → substrate
  verify → VALIDATE with no intervening scheduler decision. **Verify = substrate, decided**
  (t23 approved); report still reads as one Validation layer.
- **Audit economics (t17/t20 — research-backed, subagent sources cited in-thread).**
  Weak-tier default is sound only over mechanical artifacts: new **build-map** (CONSTRUCT
  maps every hunk → staged task; unmapped hunk = automatic finding — DO-178C traceability
  prior art), **audit lottery** (suspicion-weighted escalation + uniform-random floor — the
  Redwood AI-control pattern), judge from a **different model family** than the builder,
  build log = claims-to-verify never testimony. Judge scales with centrality×(1−conf).
- **t18 dissolved by content-pinning**: the scheduler snapshots the `✅ v` tree-hash into
  the dispatch record; verify diffs against it — no authorship tracking. Recorded as a #60
  store requirement. **NEW proposal awaiting rjs: a held-out test slice** (specs CONSTRUCT
  never sees — a hard-coding trap).
- **Renegotiation stays seam-only (t5/t19, pushed back):** `fault(plan@N)` *is* the
  request; PLAN re-entry answers revise / hold / cancel on the record; rebuilds start
  fresh (anchoring evidence), never patch the stuck draft. **Budgeted-not-counted (t6/t14,
  conceded):** progress heuristic + active licence to give up + tier-gate on indictment.
- **Bug registry (t4/t8):** findings-vs-faults distinction; `🐞` = deferred-correctness
  beside `fd`/`opt`; embeddings for dedup only, **deterministic artefact-ownership**
  assignment, reconcile-time claiming, open-bug count = scheduler re-entry pressure.
  **Local pre-drafter (t7) rejected** (anchoring evidence; the router already *is* the
  cheap-drafter pattern); deterministic template/codegen scaffolding adopted instead.

After both converge, the four move-specs are done → the #60 node-store migration becomes
unblocked (§7). The #60 issue should also inherit the new store requirements noted above

## 9. Gotchas (see `model-feedback.md` for detail)

- **Commit `plan.md`/`design.md` + `threads/` only — never stage `turn.xml`** (GUI-owned;
  always shows `M`). Set `DOCLOOP_DOC=plan.md` (or the relevant doc) on **every** CLI call
  (`thread`, `canonicalize`, `lint-turn`) or they default to `doc.md`.
- **`turn.xml` reports threads *changed this turn*, not all open threads**, and is only
  trustworthy right after a "Hand to Claude". Reconstruct open state from `threads/` +
  `git log` if turns have elapsed or the human edited without handing off.
- **Anchor plain text only** inside `:mark[…]` — bold/italic/code inside the brackets
  fragments the anchor under canonicalize. (Upstream fix **merged but unreleased** — Milkdown
  PR #2405; see `model-feedback.md` for the update recipe. Until it ships, keep bold labels
  *outside* the `:mark[]`.)
- **Preview with `npm run canonicalize -- --check workspace/<doc>` first**, then run it for
  real; `npm run lint-turn` must be `clean` before commit — **but lint-turn is not
  multi-doc aware**: with threads split across `construct.md`/`validate.md` it flags the
  *other* doc's threads as "orphaned". Verify the **union** instead (anchors across all
  workspace docs ↔ `threads/` dirs — a 10-line python check; see model-feedback 2026-07-09).
- **Edit canonicalised prose by python line-index, not exact-match `Edit`** when unicode
  (`→`, em-dashes) makes bytes un-matchable.
- **Running the GUI durably:** `npm run serve` (built, HMR-free — survives sleep/restart)
  rather than `npm run dev`, from your own terminal. See `HANDOFF.md`.
- Env: the RTK bash proxy mangles `grep`/`sed`/`diff` output — fall back to `python3`.
